# yb1-ioctl — ベンダの ioctl を 1 本だけ出す（段階 B の観察）

`tools/` の他のものが全部「読むだけ」なのに対し、**これは書く**。そこが要点。

裏 CPU のコマンドスタックは誰かが叩かないと動かないが、ベンダアプリは 1 操作
あたり 20 本前後をまとめて出すので切り分けられない（仕様 §13.5）。一方、
**待機中のベンダアプリは API を 1 本も出さない**（実測 0 件/5 秒・仕様 §12.4）。
∴ ここから 1 発だけ打てば、エントリ表（物理 `0x00010400`）の差分が
**その 1 本が生んだコマンド**になる。これで ioctl → コマンド ID の表が作れる
（仕様 §14）。

```
yb1-ioctl <device> <cmd> [byte ...]

  <device>  /dev/val_demux など
  <cmd>     トレースが出す形の要求。例 0x4028c32f
  [byte]    引数。上位から順、足りない分はゼロ埋め
```

大きさ・方向・型は `<cmd>` から取り出す（**MIPS の `_IOC` は asm-generic とは
違う**: `SIZEBITS=13`, `DIRBITS=3`, `NONE/READ/WRITE = 1/2/4`）。引数バッファは
呼ぶ前と後の両方を出すので、読み返しがそのまま見える。

ビルドは `scripts/build-yb1-ioctl.sh`（ツールチェーンは板の `build.env` の pin を
sha256 つきで取得）。静的・libc 非依存なのでベンダ rootfs にそのまま置ける。

## 注意

- **ベンダアプリの状態を壊す。** ベンダアプリが持っているハンドルに外から
  コマンドを出すため。実測では `csd` も裏 CPU も `blur` 自身も無傷のまま、
  選局だけが `501 Action Failed` になった（仕様 §14.3）。**電源で戻る。**
- 安全なのは `val_merge` 内で完結する要求だけ（`ret = 40` を返しコマンドを
  生まないもの。仕様 §14.1 の表を見ること）。それ以外を掃いたら再起動する。
- 出力は配布物ではない。ベンダ由来の解析素材（CONTRIBUTING.md §0）。
