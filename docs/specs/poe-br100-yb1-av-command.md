裏 CPU（AV サブシステム）で動くベンダ FW に、メイン CPU から**ベンダのカーネルモジュールを
通さずに**コマンドを積み、デマルチプレクサ（PID フィルタ）を組むための仕様。
生 TS の取り出し（FIFO・ドレイナー）は [生 TS の取り出し](poe-br100-yb1-ts-fifo.md)、
復調器（MXL683）の立ち上げと選局は [MBIN ファーム容器](mbin-firmware-container.md) §7 と
受信スタック仕様 §29・§84。

## 0. スコープと前提

- **裏 CPU を起こすのは、所有者の機器上の `csd.ko`**（ベンダのまま・実行時に使う）。起きた後に
  外してよい（§1）。裏 CPU を自前で起こす方向は追わない（受信スタック仕様 §80 の冒頭）。
- 裏 CPU の FW は所有者の機器の mtd5 にあるもの（`emma3sep_driver_std_op0.mem`）を実行時に使う。
  配布物には入れない。
- **限定受信（B-CAS / MULTI2 / ARIB スクランブル解除）は永久に対象外。** デスクランブラの
  デバイス・関数（`val_m2dsc`／`val_dscram`）は開かない。ECM/EMM の PID も他の PID と同じく
  フィルタに載せて運ぶだけ。

## 1. 起動（メイン CPU の側から見た手順）

1. mtd5（squashfs）を mount し、`emma3sep_driver_std_op0.mem` を物理 `0x30000` へそのまま
   書く（ヘッダは剥がさない。ベンダの `setup.sh` と同じ）。
2. `insmod csd.ko`（`CSD_MODE` は既定の `NORMAL`）。csd が起動ベクタとリセットを書き、FW が
   走り出す。FW は自分で共有メモリ `0x10000`〜`0x1ffff` を 0 で埋める。
3. 起きたことを確かめる: BHIF `+0x180`（`0x10000180`）が `0`、`+0x1ac` が `0xa0010000`。
4. `rmmod csd.ko`。**裏 CPU は走り続ける。** メイン CPU 側の SW 割り込みの許可（`+0x1a4`）は 0 に
   戻るが、`+0x1ac`・`SUB_INT_EN_0 = 0x80`・`+0x1b4 = 0x00070000` は残る。
5. 以後は §2 の経路だけで話す。ほかのベンダのモジュール（`val_merge`・`ei2c_ofdm_drv`・
   `io_controller_drv`・`fe_*`・`mem2`・`h57fmb`）は要らない（受信スタック仕様 §82）。

`csd.ko` の load は 1 回の起動で 1 度きりにする（load し直すと FW の初期化がやり直され、それまでの
設定が消える・`subcpu-control.md` §5.2）。

## 2. コマンドスタック

| 要素 | 値 |
|---|---|
| 共有メモリ | 物理 `0x10000`（KSEG1 `0xa0010000`・BHIF `+0x1ac` が指す） |
| エントリ表 | 物理 `0x10400`、32 バイト × 32 項。**環はエントリ 1〜31**（31 の次は 1） |
| データリング | `0xa0010800` から。要求と応答をここに置き、その番地（KSEG1）をエントリに書く。4 バイト境界。ベンダは全 PID の設定で `0xa00112fc` までしか使わなかった（折り返しの位置は未確認） |
| 合図 | BHIF `0x100001b0` に `0x00020000` を書く（裏 CPU の割り込み源 7） |

エントリの 8 語:

| 語 | 積むとき | 完了後 |
|---|---|---|
| 0 | `0x00020000`（保留の印。**最後に書く**） | `0x00040002` |
| 1 | `(コマンド ID << 16) \| 通し番号` | 同じ |
| 2 | 要求の番地 | 同じ |
| 3 | 要求の番地 ＋ 要求長（＝応答の番地） | 同じ |
| 4 | `0x7fffffff` | 同じ |
| 5 | `0` | **状態**（0 が成功） |
| 6 | 要求長 ＋ 応答長（バイト） | 同じ |
| 7 | `0` | 同じ |

- 手順: 要求の語をデータリングに書く → 応答の場所を 0 にする → エントリの語 1〜7 → 語 0 →
  合図。語 0 が `0x00040002` になったら、語 5 が状態、応答は語 3 の番地にある。
- **順番**: FW は環のエントリを順に取る。**通し番号の順・エントリの順に積む**（飛ばしたり
  前後させたりすると、FW は次に来るはずのエントリで待ったままになる）。
- **通し番号**: `0x01NN`。起動後の最初が `0x0100`、下位 8 ビットが数えて回る。途中が空いても
  FW は気にしない（実測）。
- **エントリ 0 は環ではない。** ベンダは状態の問い合わせ（`0x191b`）をエントリ 0 に積むことが
  あるが、この合図では処理されない。使わない。
- 応答の合図（`SW_INT` `0x100001a0` の bit 0）は受け手がいないと立ったまま残る。消さなくても
  次のコマンドは完了する。
- **触ってはいけない**: `+0x1b4` に静止値 `0x00070000` 以外を書くこと（AV が固まる）、
  `+0x180`（リセット）への書き込み、3 つめのプロセッサの組（`+0x1d0`〜）。

## 3. コマンド

ベンダの ioctl（`/dev/val_demux`）を記録して対応を取った（受信スタック仕様 §81・§83）。
要求／応答はバイト数。「ctx」はベンダが渡すカーネル空間の番地で、裏 CPU には不透明な値。

| コマンド | 要求 → 応答 | 意味（ベンダ ioctl） |
|---|---|---|
| `0x1900` | 0 → 0 | Initialise（`nr=0x01`）。起動ごとに 1 回 |
| `0x1901` | `{1}` → ハンドル | デバイスを開く（`nr=0x02`）。ベンダは 3 つ開く: `0x00010000`（機器 1）、`0x01010001`、`0x02010002`（機器 2） |
| `0x1904` | `{機器, 3}` → 0 | 入力源（`nr=0x05`）。3 ＝ 復調器の TS |
| `0x1919` | `{n, ctx, 0}` → 0 | 機器の設定（`nr=0x65`、n = 0, 1） |
| `0x1913` | `{n, ctx, 0}` → 0 | 機器の設定（`nr=0x64`、n = 0, 1） |
| `0x194f` | `{機器 2, 1}` → 0 | 機器を開いた直後（`nr=0x48`） |
| **`0x190a`** | **`{種別, 自分の要求 + 12, 機器, 0xffffff00}` → ハンドル** | **フィルタの確保**（`nr=0x0b`）。種別 7 ＝ PID フィルタ（FIFO に入れる）、6 ＝ ペイロード。ハンドルは `(機器 << 24) \| 0x100000 \| 番号` |
| `0x191a` | `{ハンドル}` → 番号 | 確保のたびにベンダが続けて積む（`nr=0x19`） |
| **`0x190b`** | **`{ハンドル, PID}` → 0** | **PID の設定**（`nr=0x0c`）。**無効のときだけ**（有効なら状態 8） |
| **`0x190c`** | **`{ハンドル, 1}` → 0** | **有効化**（`nr=0x0d`） |
| **`0x190d`** | **`{ハンドル}` → 0** | **無効化**（`nr=0x0e`） |
| `0x194c` | `{ハンドル, 1}` → 0 | 機器 2 のフィルタで有効化の前（`nr=0x32`） |
| `0x194a` | `{機器 2, 1, 2, 5}` → `0x2002` | 確保系（`nr=0x30`）。起動ごとに 1 回 |
| `0x194d` / `0x194e` | `{0x2002}` 系 → 0 | `nr=0x33`／`0x34` |
| `0x1914` `0x1915` `0x1916` `0x191b` `0x1929` `0x192c` `0x192d` `0x192e` `0x1931` `0x1932` | | ペイロード（PES）側（受信スタック仕様 §43）。生 TS には要らない見込み |
| `0x1909` / `0x1928` / `0x1927` | | ベンダの列でも状態 3 で失敗する（既知・§34.3） |

## 4. フィルタ（種別 7）の振る舞い

| 状態 | PID 表の項（SRAM `0x1003066c + 2 × 番号`） | FIFO に入るもの |
|---|---|---|
| 確保していない | `0x1fff` | 何も入らない |
| 確保し PID を設定（有効・無効を問わない） | `PID`（有効なら bit15） | **その PID のパケット** |
| PID `0x1fff` を設定 | `0x1fff`／`0x9fff` | **ヌル** |

- **FIFO に入るかは PID の値だけで決まる。** 有効化（bit15）は FIFO の門ではない。
- **PID を変えるには、無効化（`0x190d`）してから `0x190b`。** FIFO のためには有効化は要らない。
- 1 機器 36 本（機器 1 → FIFO 0、機器 2 → FIFO 2）。1 つの PID は 1 本のフィルタにだけ載せる
  （機器をまたいで載せると同じパケットが 2 回出る）。
- 使わないフィルタは、多重に現れない PID に置く（確保したまま止める手段は未確認）。
- 選局し直しても、フィルタはそのまま残る（新しい多重の一致する PID が入る）。

## 5. 生 TS に要る最小の組と、検証の範囲

### 5.1 ★ 最小の組（6 種・受信スタック仕様 §85）

```
0x1900  Initialise                              起動ごとに 1 回
0x1901  {1}  × 3                                → 機器 0・1・2（開いた順に番号が付く）
0x1904  {機器 0, 3}、{機器 2, 3}                 入力源＝復調器の TS
0x190a  {7, 自分の要求 + 12, 機器, 0xffffff00}  → フィルタ   ┐ PID ごとに
0x190b  {フィルタ, PID}                                      ┘（有効化は要らない）
0x190d  {フィルタ}                               選局し直すとき、PID の差し替えの前に
```

これで機器 0 → FIFO 0、機器 2 → FIFO 2 に、載せた PID がすべて入る。ベンダの列にある
`0x1919`/`0x1913`（不透明な ctx つき）・`0x194f`・ペイロード側・`0x191a`・`0x194c`・`0x190c` は
要らない。

### 5.2 検証の範囲

- **検証済み**: 電源投入 → csd で起動 → `rmmod val_merge csd` → ベンダの全 PID の列（§3 の
  コマンド 257 本）をそのまま積む。状態と応答がすべてベンダの経路と一致し、PID 表も 1 語も違わず、
  FIFO に TS が入った（ドレイナーの 10 秒で約 11 万本・同期の乱れ 0）。ベンダのモジュールを csd と
  GPL の i2c だけにした起動でも同じ（受信スタック仕様 §81・§82）。フィルタの状態遷移（§4）。
  最小の組（§5.1）で 5 PID（受信スタック仕様 §85）。
- **未検証**: 最小の組で全 PID（約 50 本）を載せたときの照合、データリングの折り返し位置、
  エントリ 0 の出し方、フィルタの解放、参照受信機とのビット単位の照合（§81 の構成で）。
