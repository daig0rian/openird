段階 C の chardev 契約（CLAUDE.md §4.1）が要る「生 TS」を、この機種で得る方法の仕様。
実装者はこの文書だけを見て、生 TS の経路（FIFO の設定・取り出し・受け渡し）を書ける
ことを目指す。観察の経緯と試行錯誤は
[受信スタック仕様](poe-br100-yb1-reception-stack.md) の §73〜§78 にある。

## 0. スコープ

- 対象: 復調器（MXL683）から SoC に入った TS を、**スクランブルされたまま**、188 バイトの
  パケットとしてメイン CPU 側に取り出すこと。
- 出力は「規格どおりに列挙した全 PID の TS」で、**ヌル（`0x1fff`）だけを含まない**（§4.5）。
- **限定受信（B-CAS / MULTI2 / ARIB スクランブル解除）は永久に対象外。** ECM/EMM の PID も
  他と同じくパケットを運ぶだけで、中身は解釈しない（px4_drv が全 PID を渡すのと同じ立場）。
- 前提として、フロントエンドの選局（`mbin-firmware-container.md`・受信スタック仕様 §30）と、
  裏 CPU の FW のロード・デマルチプレクサの初期化（受信スタック仕様 §24.3/§43/§72）が済んでいる。

## 1. 全体の流れ

```
MXL683 ──TS──▶ [TS 入力＋PID 選別]    PID 表に載った PID の 188B だけ・スクランブルされたまま
                     │
                     ▼
        AV データ SRAM 0x10030000〜0x1003ffff   ← メイン CPU から読める（書かない）
          FIFO 0 / 1 / 2：220B のスロット（到着時刻 27MHz＋188B）
                     │              └─▶ 裏 CPU の FW（PES/セクションの組み立て。この仕様では使わない）
                     │ メイン CPU の高分解能タイマ（100µs）で全スロットを見て、到着時刻順に取る
                     │   流量の少ない FIFO：CPU でリングへ（先に済ませる）
                     │   流量の多い FIFO：XDMA でリングへ直接（アドレス順）
                     ▼
        DRAM のリング ＋ 到着順の待ち行列（要素の番号）
                     │ read()
                     ▼
                 188B のパケット列（chardev）
```

## 2. この仕様が成り立つ条件

- ベンダ FW 2.1.17 r3 の裏 CPU の FW（mtd5 `emma3sep_driver_std_op0.mem`）で観察した。
  §4〜§5 の SRAM 上の配置は **この FW の実行時データ** であり、FW が変われば変わりうる。
  実装は §4.2 の手順で配置を実行時に確かめ、合わなければ使わないこと。
- メイン CPU は単一コア。カーネルは 2.6.27（`CONFIG_HIGH_RES_TIMERS=y`・`CONFIG_PREEMPT=y`・
  `CONFIG_DMA_NONCOHERENT=y`）。

## 3. AV データ SRAM

| 項目 | 値 |
|---|---|
| 物理番地 | `0x10030000`〜`0x1003ffff`（64KB） |
| 中身 | 裏 CPU のデータメモリ。デマルチプレクサの初期化（`nr=0x01`）で書かれる |
| メイン CPU から | `ioremap_nocache`（カーネル）／`/dev/mem` の mmap（ユーザランド）で**読める**。読んでも止まらない |
| 読み出しの速さ | **1 語（32bit）約 0.23µs**、上限約 17 MB/s。キャッシュ経由（行の無効化＋KSEG0）でも同じ |
| 書き込み | **しない**（裏 CPU の変数である） |

`0x10000000`〜`0x100fffff` の範囲は読んでも止まらないが、`0x11000000` の窓は読むと止まる
（受信スタック仕様 §54.1）。

## 4. TS 入力 FIFO

### 4.1 制御ブロック

FIFO n の制御ブロックは SRAM の `0xec00 + 0x80·n`（n = 0, 1, 2）。

| オフセット | 内容（観察） |
|---|---|
| `+0x00` | 構成（起動直後 `0x000a0000`、初期化後 `0x130a0842`／`0x130a0843`） |
| `+0x04` | 1（有効） |
| `+0x08` / `+0x10` | 溜まっている個数 |
| `+0x14`〜`+0x2c` | **空きスロットの待ち行列（7 語）**。値はスロットの SRAM オフセット |
| `+0x34` | `0xbc`（188＝パケット長） |
| `+0x38` / `+0x3c` | `0x471fff00` / `0xff1fff00`（sync と PID の値・マスクの形。用途は未確定） |
| `+0x54` | 時刻（裏 CPU が書く） |

### 4.2 スロット

- 1 スロット 220 バイト（`0xdc`）。スロットは FIFO ごとに **220 バイト刻みで連続**して並ぶ。
- スロット内: **`+0x0c` 到着時刻**（32bit、27 MHz）、**`+0x10` から TS パケット 188 バイト**
  （`0x47` から、ヘッダ込みで素のまま）。
- スロット数は FIFO ごとに違う（観察した FW で）:

| FIFO | スロット（SRAM オフセット） | 数 |
|---|---|---|
| 0 | `0x8004`〜`0x852c` | 7 |
| 1 | `0xa264`〜`0xa6b0` | 6 |
| 2 | `0x9134`〜`0x9738` | 8 |

- **見つけ方**: 待ち行列（7 語）を繰り返し読み、値の和集合を取る。待ち行列には、いま埋めて
  いる・処理中のスロットは載らないので、1 回読みでは足りない。**少なくとも 100ms、新しい値が
  50ms 出なくなるまで**読む（ただし流れがあること）。得た集合をアドレス順に並べ、隣り合う差が
  すべて 220 であることを確かめる（欠けがあれば差が 440 になる）。

### 4.3 到着時刻

- **27.000 MHz**（実機の稼働時間との突き合わせで実測）。32bit で約 159 秒ごとに一巡する。
  前後の比較は 32bit の差を符号付きで見る。
- 到着間隔は **32.0µs（864 刻み）単位**に量子化され、**最小 32.0µs**。32µs 間隔の連続は最長 2 回
  （映像 PID で 6 万本×3）。

### 4.4 埋まる順番

- 待ち行列は**空きスロットの列**である。ハードウェアは先頭を使い、裏 CPU は処理を終えた
  スロットを戻す。
- ∴ **埋まる順番はアドレス順ではない**（PID が多いと、ほぼ毎周期アドレス順から外れる）。
  取り出しは到着時刻で並べて行う（§7.2）。
- あるスロットが再利用されるのは、最短で「スロット数 − 1」本後。

### 4.5 何が入るか

- その FIFO に対応する機器の **PID 表に載った PID のパケットだけ**（§5）。全 PID を通す設定
  （`ControlHardwarePidFiltering` 相当・`nr=0x48 {機器,0}`）でも増えない。
- **スクランブルされたパケットは scrambling_control（2/3）のまま入る。** デスクランブラは経路に
  入らない（OpenIRD の構成では開かない）。
- **ヌル（`0x1fff`）を入れる手段は見つかっていない。**

### 4.6 機器と FIFO

| 機器（デマルチプレクサのデバイス） | FIFO | 制御ブロック |
|---|---|---|
| 機器 1（`nr=0x02` の 1 つめ、ハンドル `0x00010000`） | 0 | `0xec00` |
| 機器 2（2 つめ、ハンドル `0x02010002`） | 2 | `0xed00` |
| 機器 3（ハンドル `0x01010001`） | 1（推測・未検証） | `0xec80` |

## 5. PID 表とフィルタ

### 5.1 PID 表

- SRAM の `0x1003066c` から 16 ビット × 108 項。添字＝フィルタ番号。
- 各項: bit15＝有効、下位 13 ビット＝PID、未使用は `0x1fff`。
- **bit15 は FIFO の入口の門ではない**（無効化しても流入は止まらない）。取り出す側は PID 表を
  読む必要は無い。

### 5.2 フィルタの数

- **1 機器 36 個**（108 項の 3 等分）。機器 1 は番号 `0x23` から下へ `0x00`、機器 2 は `0x6b`
  から `0x48`。37 個目の確保は `ret=-6`。
- 他のフィルタが持っている PID を渡すと、有効化が `-8` になることがある（受信スタック仕様
  §19.4）。一方、機器 1 と機器 2 に同じ PID を載せると、同じパケットが両方の FIFO に入った
  （§77.2）。∴ **1 つの PID は 1 つのフィルタにだけ載せる**（出力が重複しないように）。

### 5.3 FIFO に載せる手順（PID フィルタ＝種別 7）

`/dev/val_demux` 系の ioctl（`_IOW`・大きさ 40・型 `0xc3`、要求語は `0x8028c3NN`）で:

| 順 | nr | 引数 | 意味 |
|---|---|---|---|
| 1 | `0x0b` | `{7, パラメタの番地, 機器ハンドル, 応答番地}` | 種別 7 のフィルタを確保。ハンドル（機器 1 は `0x0010xxxx`、機器 2 は `0x0210xxxx`＝上位バイトが機器）が応答番地に書かれる |
| 2 | `0x0c` | `{フィルタ, PID}` | PID を設定 |
| (3) | `0x32` | `{フィルタ, 1}` | 機器 2 のフィルタでは有効化の前に出した（ベンダの列に倣った） |
| 4 | `0x0d` | `{フィルタ, 1}` | 有効化 |

- リングの登録も PES の組み立ても要らない。
- 機器 2 のフィルタは `/dev/val_demux1` で確保し、設定は `/dev/val_demux` で出した
  （ドライバの状態は open ごと。受信スタック仕様 §34）。
- デマルチプレクサの状態はプロセスが終わっても消えない（電源で戻る）。

これらの ioctl はベンダ `val_merge.ko` を通るので、段階 C では受信スタック仕様 §72 の手順
（コマンドスタック＋合図）で同じコマンドを自分で積むことになる（未実装）。

## 6. PID の列挙

### 6.1 規則（ARIB TR-B14 英訳 v6.7-E1 による）

1. **固定 PID**（Vol.4 Table 5-4）: `0x0000` PAT、`0x0001` CAT、`0x0010` NIT、`0x0011` SDT、
   `0x0012`/`0x0026`/`0x0027` EIT、`0x0014` TOT、`0x0023`/`0x0028` SDTT、`0x0024` BIT、
   `0x0029` CDT の 12 個。まれにしか送られない表があるので、実在を待たずに載せる。
2. **PAT** → NIT と各番組の PMT。
3. **PMT** → PCR、各 ES、番組ループと ES ループの **CA 記述子（タグ `0x09`）とアクセス制御
   記述子（タグ `0xF6`）** が指す PID（ECM）。
4. **CAT** → 同じ 2 種の記述子が指す PID（EMM）。

アクセス制御記述子（`0xF6`）は CA 記述子と同じ構造（CA_system_ID 16 ビット、伝送路 3 ビット、
PID 13 ビット）で、地上デジタルでは ECM/EMM の PID をこちらで告知することがある（TR-B14
Vol.4 Table 5-6・30.2.2.2）。**`0x09` だけを読むと PID を取りこぼす。**

PAT・PMT・CAT の版番号が変わったら列挙し直す（PMT は番組構成で変わる。副音声の PID が
出入りするのを観察した）。

### 6.2 557 MHz（TSID `0x7fe0`）の例

規則で 50 個（うち実在しない告知 PID を含む）。実在は 36 個（ヌル以外 35 個）で、この 35 個が
参照受信機の TS のヌル以外すべて（受信スタック仕様 §76.1）。

### 6.3 機器への振り分け

1 機器 36 個（§5.2）なので、50 個を 2 機器に分ける。取り出しの負荷の偏りに合わせ、**流量の多い
PID を XDMA で吸う FIFO に、少ない PID を CPU で吸う FIFO に**載せる。557 MHz での振り分け:

| 機器 2（FIFO 2・XDMA） | 機器 1（FIFO 0・CPU） |
|---|---|
| PAT、番組の映像・音声・字幕・データ・PCR、ワンセグの ES・PCR、番組 `0xfff0` の ES（計 32） | 固定 SI、PMT、ECM、EMM（計 18。毎秒約 150 本） |

## 7. 取り出し

### 7.1 周期

- ハード割り込み文脈の高分解能タイマ（2.6.27 の `hrtimer`、`HRTIMER_CB_IRQSAFE_UNLOCKED`）で
  **100µs** ごと。150µs ではまれに 1 本欠け、400µs では欠ける（最新の 1 本を 1 周期待つので、
  取るまでの遅れは周期の約 2 倍＋転送。FIFO 2 が一巡する最短は 352µs、FIFO 0 は 6.8ms）。
- タイマ割り込みそのものが 1 回約 6µs（コールバックの外）＝100µs で CPU の約 6%。
- 1 周期の中の順番: ① 前の転送の回収と XDMA で写す FIFO の走査 → ② **CPU で写す FIFO**
  （走査と写し）→ ③ XDMA の転送の起動 → ④ 公開。②を③より先にするのは、XDMA が SRAM を
  読んでいる間は CPU の SRAM 読みが 1 語 0.3µs → 1.8µs に落ちるから。

### 7.2 どのパケットを取るか

1. FIFO の**全スロットの到着時刻を読む**。前回そのスロットから取った時刻と違えば新しいパケット。
2. 新しいものを**到着時刻の古い順**に並べる。
3. **いちばん新しい 1 本は、次の周期にも同じ時刻であれば取る**（到着時刻はパケットより先に
   書かれるので、書き込み途中を掴まないため）。それ以外は今の周期で取る。

### 7.3 CPU で写す

- 188 バイトを 32bit 読み 47 回で、リングの要素へ**非キャッシュの別名で**写す（§7.5 の
  キャッシュの約束）。1 本約 15.5〜20µs。流量の少ない FIFO（毎秒約 150 本）に使う。
- 写した後に到着時刻を読み直し、変わっていれば**捨てる**（写している間に再利用された）。
- 要素の範囲のキャッシュを無効化してから待ち行列に入れる。

### 7.4 XDMA で写す

レジスタと使い方は GPL カーネル（`include/asm-mips/emma/emma3sep.h`、
`drivers/mtd/nand/nand_emma.c`、`arch/mips/emma/emma3sx/platform.c`）による。

| レジスタ（XDMA `0x10009000`） | 内容 |
|---|---|
| `+0x088` LIST_ENABLE | bit n を書くとチャネル n が始まる。終わると自分で 0 に戻る |
| `+0x100 + 0x20·n` MEM_LIST0 | 転送元（物理番地） |
| `+0x104 + 0x20·n` MEM_LIST1 | 転送先（物理番地） |
| `+0x108 + 0x20·n` MEM_LIST2 | 長さ（バイト）。**0 になったら完了** |
| `+0x10c + 0x20·n` MEM_LIST3 | 設定: bit 28 転送元を増やす、bit 29 転送先を増やす、**bit 26 転送元が DRAM、bit 27 転送先が DRAM**、bit 16 完了を MAIN_INT2 に立てる |
| `+0x110 + 0x20·n` MEM_LIST4 | 0（リストを使わない） |
| `+0x508` MAIN_INT2 | bit n＝完了（MEM_LIST3 の bit 16 を立てたときだけ立つ） |

- **SRAM から DRAM へは `MEM_LIST3 = 0x38000000`**。bit 26 を立てると転送元を DRAM として
  扱い、SRAM の中身にならない。bit 27 を立てないと DRAM に届かない（アドレスは進むのに）。
- チャネル: 0 は NAND ドライバ、1 はベンダアプリ（`platform.c` の注記）。**2 を使う**
  （段階 C のリグでは起動以来未使用のまま＝電源投入時の値が残っていた）。
- 速さ: SRAM から 188 バイトで約 12.5µs（約 17 MB/s。SRAM 側が律速）。CPU は 6 レジスタの設定
  （約 1µs）だけで、転送を待たない。
- 手順（1 周期に 1 回）:
  1. 前の周期の転送を回収する: MEM_LIST2 が 0 でなければ、その FIFO はこの周期は休む。
     0 なら転送した範囲のキャッシュを無効化し、各スロットの写しを確かめる（下）。
  2. 取るパケットのスロットのうち、**アドレスの最小から最大までの範囲**（間の他のスロットも
     含む）を、最小スロットの到着時刻から最大スロットのパケット末尾まで、**リングの書き込み
     位置へ直接** 1 回で運ぶ（要素＝スロットの写しなので、並びはスロットのアドレス順）。
     リングに空きが無ければ小さな作業領域へ運ぶ（失われた本数を数えるためだけ）。
  3. 回収では、**到着時刻の古い順に**、確かめた要素の番号を待ち行列に入れる（§7.5。同じ PID の
     順番を守る。アドレス順に入れてはいけない）。範囲に挟まった準備前のスロットの要素は入れない。
- **写しを信用する条件**: 写しの先頭の到着時刻が期待どおりであること（DMA が読み始めた時点で
  スロットは書き換わっていない）。加えて、読み終える前に再利用が始まっていないこと:
  スロット数 N、そのパケットの後ろにすでに届いている本数 m、範囲内での位置 p、走査から転送
  開始までの遅れ d について、`(N − 1 − m − 2) × 32µs > d + 2 + 13 × (p + 1) µs` なら信用する。
  満たさないときだけ回収時に SRAM の到着時刻を読み直し、変わっていれば捨てる。

### 7.5 受け渡し

- **リング**: 220 バイトの要素（スロットの写し＝到着時刻＋188B）の物理的に連続した列と、
  末尾に**転送 1 回ぶん（16 要素）の予備**。書き込み位置は要素単位の通し番号で数え、転送は
  予備に食い込んでよい（リングの端で切らない）。
- **待ち行列**: 読み手に渡すのは「要素の番号」の列で、**到着順**に並ぶ。各項は「これを読み
  終えたらリングのどこまでが空くか」（`free_to`）も持つ:
  - 転送の要素: 最後の 1 つはその転送の範囲の末尾、それ以外は範囲の先頭。
  - CPU で写した要素: 自分の末尾。ただし**まだ回収していない転送がその手前にあれば、その
    転送の先頭で止める**（その転送の要素は回収のときに初めて待ち行列に入るので）。
  - 書き手は、読み手が読み終えた項の `free_to` だけから空きを知る（書き手と読み手の間に
    ほかの共有状態は要らない）。待ち行列の長さはリングの要素数より大きい 2 の冪。
- **キャッシュの約束**（`CONFIG_DMA_NONCOHERENT`）: リングの行はキャッシュ上で**決して dirty に
  しない**。220 バイトの要素は 32 バイトの行に揃わず、隣の要素と行を分け合う。書き戻しが
  起きると、隣に DMA が置いたばかりの中身を潰しうる。∴ リングに書くのは DMA と、CPU の
  非キャッシュの別名だけ。読み手は読むだけ。書かれた範囲は無効化してから公開する。ロード時に
  リング全体を書き戻し・無効化しておく。
- 周期の終わりに、その周期に入れた項をまとめて公開する。
- 読み手は 188 バイト単位で読む。**同じ PID の中は到着順**。PID 間の並びは、XDMA の FIFO の
  パケットが 1 周期遅れるぶん前後しうる。
- 読み手を起こすのはまとめて（64 本溜まるか 10ms）、**読み手が待っているときだけ**
  （待っていないのに毎周期起こすと、それだけで数 % を失う）。
- `open()` は「今」から読む（未読の項を捨てる）。読み手がいない間はリングが埋まり、以後の
  パケットは溢れとして数えるだけになる。

### 7.6 コスト（実測）

「系全体」は、スタックしか触らない空回しの回数がドレイナー無しに比べてどれだけ減ったか
（`yb1-mem 0 1 burn`）。2.6.27 の `/proc/stat` はハード割り込みの時間が見えないので使えない。

| 条件（全 PID・ヌル以外 毎秒約 10,900 本・読み手 `cat`） | コールバック | 系全体 |
|---|---|---|
| 作業領域を経て CPU でリングへ写す版（受信スタック仕様 §77.4） | 25.6% | 40.4% |
| **§7 の版**（統計なし） | **13.2%** | **30.8%** |
| §7 の版・読み手なし | 11.2% | 21.5% |
| タイマ割り込みだけ（コールバックは何もしない） | 0 | 6.2% |

- §7 の版のコールバック: 毎周期 入口 1.1µs＋XDMA 側の走査 3.3µs（8 語）＋CPU 側の走査 2.1µs
  （7 語）、転送ごとに回収 1.7µs＋起動 2.2µs、CPU で写す 1 本約 18µs。
- 読み手の `read()` は 1 本約 3.4µs（DMA の後の DRAM の読み。先読みは効かない）。緩衝が
  キャッシュに収まらない大きな読み（47KB）は 1 本 5.3µs に悪化する。

## 8. 検証の方法と結果

- **参照受信機**: 別ホストの PC 用チューナ（PX-M1UR・recisdb・`--no-decode`）で同じ局を
  同時に取り込み、両方でパケットごとに「PID・連番・CRC-32」を取り、ハッシュだけを突き合わせる
  （中身はどちらのホストからも出さない）。道具は `tools/host/tsref.py`・
  `tools/host/tshashcmp.py`・`yb1-mem @file 0 <len> hashes`。
- 結果:

| 走行 | 結果 |
|---|---|
| 映像 PID 1 本・10 秒 | 91,659 本すべてビット単位で一致、欠け 0・化け 0 |
| **全 PID（35）・10 秒** | **ヌル以外 110,911 本を 100% 網羅**（35 PID すべて本数比 1.000）。照合できた 22 PID は全数ビット一致・欠け 0・化け 0。残り 13 PID は同じ内容のパケットが繰り返し位置を決められないが本数は一致 |
| 全 PID・ロードから 131 秒 | 145 万本で連番の途切れ 0・破れ 0 |

## 9. 未確定・既知の問題

- **CPU は系全体で約 31%**（§7.6。コールバック 13%・タイマ割り込み 6%・読み手 5〜6%）。
  割り込みの回数は FIFO 2 の一巡（352µs）に縛られて周期 100µs が上限に近い。最新の 1 本を
  1 周期待たずに済めば延ばせる（未検証）。毎周期 15 語の走査は、SRAM に「単調に増える到着の
  計数」があれば 1 語にできる（未確認）。
- **XDMA の転送が周期内に終わらないとき**、その FIFO の周期を丸ごと休む。メモリが混むと
  取り残す（受信スタック仕様 §76.3）。
- **FW 版への依存**（§2）。制御ブロック・スロットの配置・PID 表の位置はこの FW の実行時データ。
- 機器 3 と FIFO 1 の対応は未検証。制御ブロック `+0x38`/`+0x3c` の意味は未確定。
- **ヌルは出せない**。出力はヌル抜きの TS になる。下流（recpt1 系）での扱いは未確認。
- PID の設定はまだベンダ `.ko` の ioctl 経由。§72 の手順での置き換え、列挙と振り分けの自動化
  （選局・版の変化への追従）は未実装。
