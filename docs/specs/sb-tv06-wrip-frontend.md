段階 C の chardev が要る「選局・ロック・C/N」を、この機種でベンダのモジュール無しに行うための
仕様。実装者はこの文書と、メインラインの `tc90522.c`・`tda826x.c` だけを見て書けることを目指す。
生 TS の経路（デマルチプレクサと FIFO）は YB1 と共通で、
[AV のコマンド経路](poe-br100-yb1-av-command.md) と [生 TS の取り出し](poe-br100-yb1-ts-fifo.md)
による（この機種で成り立つことの確認は [bring-up](sb-tv06-wrip-bringup.md) §10）。

## 0. スコープ

- 対象: 復調器 Toshiba TC90532XBG、地上のチューナ MaxLinear MxL601RF、衛星のチューナ
  Philips TDA8263HN の、**I2C で行う初期化・選局・状態読み・待機**。
- 対象外: 限定受信（永久に）。B-CAS カード（`val_scard`）。
- **アンテナへの給電は、この機種のハードに無い**（§8.1）。
- **ファーム転送は無い。** YB1 の MXL683 と違い、どのチップも電源投入後にレジスタを
  書くだけで動く（起動から選局までの全メッセージを記録して確認）。

## 1. 接続

| 項目 | 値 | 根拠 |
|---|---|---|
| バス | **GPL の `i2c-emma` のバス 1**（`/dev/i2c-1`・`emma_i2c_1`・`EMMA_PIIC1`・100 kHz） | `/proc/interrupts` の `emma-iic`（Linux IRQ 65）・バスの記録 |
| TC90532 の地上（OFDM）側 | アドレス **`0x10`** | 記録 |
| TC90532 の衛星（PSK）側 | アドレス **`0x11`** | 記録 |
| MxL601RF | 地上側のゲートの奥・8 ビットのアドレス `0xc0` | 記録 |
| TDA8263HN | 衛星側のゲートの奥・8 ビットのアドレス `0xc0` | 記録 |
| **電源** | **SoC の GPIO43（出力）を 1 にする**と復調器が I2C に応答する。0 では応答しない（`-EREMOTEIO`） | GPIO の読みと、ベンダアプリ抜きの起動での入切 |

- **GPIO43 はベンダアプリが上げている**（アプリ抜きの起動では 0 のままで、バス 1 には誰も
  応答しない）。0 → 1 にすると復調器のレジスタは初期値に戻っている（地上側 `1c` = `0x50`、
  衛星側 `1c` = `0x55`）ので、§2 の初期化からやり直す。GPIO は GPL の `zpio`
  （`drivers/gpio/emma-gpio.c`・gpiolib）で、データの書き込みはマスクレジスタで 1 ビットだけ
  開けて行う（同ファイルの `zpio_io_set_core`）。
- **ゲート**: 復調器のレジスタ `0xfe` に「チューナのアドレス（8 ビット）＋チューナへ送るバイト列」を
  書くと、そのままチューナへ中継される（メインライン `tc90522.c` の I2C アダプタと同じ形）。
  - 書き込み: `[0xfe, 0xc0, バイト列…]` を 1 メッセージで。
  - 読み出し: `[0xfe, 0xc1]` を書き、続けて n バイト読む。
- **復調器のレジスタ読み**は「レジスタ番号 1 バイトを書く」「n バイト読む」の 2 メッセージ
  （ベンダは間に STOP を置く。繰り返し START でも読める・§9）。
- **MxL601 への書き込みは「レジスタ, 値」の組の列**で、1 メッセージに最大 5 組を詰める。
  レジスタ `0x00` はページ切り替え（`00 01` でページ 1、`00 00` でページ 0）。
- **TDA8263 への書き込みは「副アドレス, 値」**で、副アドレスはレジスタ番号 × `0x10`
  （`0x00`, `0x10`, … `0x90`）。ベンダは 1 メッセージに 1 レジスタずつ書く。値の意味は
  メインライン `tda826x.c` の並び（レジスタ 2・3 が分周比、ほか）と対応する。

## 3. 待機と復帰

ベンダアプリは、視聴も選局もしていない間、フロントエンドを待機に入れる（選局の確認から
約 15 秒後）。待機中も復調器は I2C に応答する。

**待機に入れる**（地上を受けていた状態から）:

```
0x10 ゲート: 12 00 → 0b 00            MxL601 の選局を止め、チューナを止める
0x11: 13 80   1e 28   17 01           衛星側を止める（13 は読んで bit7 を立てる・1e は bit3）
0x10: 03 80 → 03 90   1c b0           地上側を止める（03 は 2 段・1c は bit7）
```

**地上へ復帰**（待機から、または衛星から）:

```
0x11: 13 80   1e 28   17 01
0x10: 03 80（待機からは）／03 00（初期化の直後は）   1c 30   0e 01
0x11: 07 07
```

**衛星へ切り替え**（地上から、または待機から）:

```
0x11 ゲート: 60 08 → 約 16 ms → 60 00
0x10 ゲート: 12 00 → 0b 00
0x10: 03 80 → 03 90   1c b0           地上側を止める
0x11: 17 00   13 00   1e 20           衛星側を起こす
0x10: 0e 07
0x11: 07 01
```

`0x11` の `17 01`／`17 00` と `0x10` の `03 90`／`03 80` は、メインライン `tc90522.c` の
衛星側・地上側の sleep／wakeup と同じ書き込み。

`0x10` の `0e` は地上で `01`、衛星で `07`。`0x11` の `07` は地上で `07`、衛星で `01`。
TS の出力はどちらの波でも SoC の同じ入力に出る（デマルチプレクサの入力源は変えない・
[bring-up](sb-tv06-wrip-bringup.md) §10）ので、この 2 つが出力の切り替えとみられる【推定】。

## 4. 地上の選局

周波数 f は物理チャンネルの中心（MHz・整数。UHF 13〜62 ch は `473 + 6 × (ch − 13)`）。

全体の形は、メインライン `tc90522.c` の「IF の AGC を手動にする → チューナを設定する → AGC を
自動に戻す → 復調をリセットする」（`tc90522_set_if_agc` と `reset_ter`）と同じ。地上側の
`25 00`・`23 4d`／`23 4c`・`01 40` はメインラインと同じ値。

**(1) 復調器の前処理 `0x10`**（AGC を手動に）:

```
47 を読み、bit7 を落として書く → もう一度読み、bit7 を立てて書く
25 00   20 00
23 を読み、bit0 を立てて書く（4c → 4d）
```

**(2) MxL601（ゲート）**:

```
0b 01                               チューナを動かす
12 01                               （待機からの最初の 1 回だけ。約 36 ms 待つ）
0f 20
10 LL  11 HH                        周波数の語（下）
00 01  31 XX  00 00  7c YY          周波数帯で決まる 2 値（下）
12 00  14 13  13 04
12 01                               選局の開始。約 36 ms 待つ
```

- **周波数の語 = round(64 × (f + 1/7))**（16 ビット。`LL` が下位・`HH` が上位）。
  例: 473 → `0x7649`、557 → `0x8b49`、767 → `0xbfc9`。YB1 の MXL683 と同じ式
  （[受信スタック仕様](poe-br100-yb1-reception-stack.md) §84）。
- **`XX`／`YY`**: f ≤ 695 で `81`／`1f`、f ≥ 701 で `91`／`9f`。
- 上の 2 つ以外に周波数で変わる書き込みは無い。**VHF・CATV 帯も同じ**（93〜767 MHz を 6 MHz 刻みで
  掃いた 114 点すべてで、周波数の語は同じ式、`XX`／`YY` は 695 以下が `81`／`1f`）。

**(3) 復調器の後処理 `0x10`**（AGC を自動に戻し、リセット）:

```
23 を読み、bit0 を落として書く（4d → 4c）
01 40                               復調のリセット（メインラインの reset_ter）
```

- ベンダはこの間に `b0`・`b2`（7 バイト）・`4f` も書くことがある。直前に受かったときの
  伝送パラメタ（TMCC）を先に与えてロックを速める操作とみられ【推定】、初めての周波数では
  書かない。**書かなくてもロックする**（§9）。
- ロックしないと、ベンダは (1) の `47` と (3) の `01 40` を約 100 ms おきに 3 回まで繰り返す。

## 5. 衛星の選局

周波数 f は BS/CS の IF（MHz・整数）。この基板が受けるのは右旋の BS 12 波と CS 12 波。

形は地上と同じ（AGC を手動に → チューナ → 自動に戻す → リセット）。メインラインの
`tc90522_set_if_agc` は衛星側で `0a`・`10`・`11`・`03` の同じ 4 レジスタを書く（値は、
メインラインが `10` に `b0`／`b1`、`11` に `00`／`40` を書くのに対し、この基板の線上では下のとおり）。

**(1) 復調器の前処理 `0x11`**: `0a 00`  `11 00`  `10` を読み bit1 を落として書く（`b2` → `b0`）  `03 01`

**(2) TDA8263（衛星側のゲート。副アドレス, 値を 1 メッセージずつ）**:

```
00 01
10 NN            周波数で決まる値（下の表）
20 HI  30 LO     分周比 = f。HI = f >> 7、LO = (f << 1) & 0xff
40 88
50 f0
60 83
70 82（BS）／81（CS）
80 1a
90 d0
（ゲートから 4 バイト読む: [fe c1] → 例 45 83 ff ff）
50 f0
```

| | f と `NN` |
|---|---|
| BS | 1049 `23`・1087 `23`・1126 `24`・1164 `24`・1202 `25`・1241 `26`・1279 `27`・1318 `27`・1356 `28`・1394 `29`・1433 `2a`・1471 `2b` |
| CS | 1613 `2e`・1653 `2e`・1693 `2f`・1733 `2f`・1773 `30`・1813 `31`・1853 `32`・1893 `32`・1933 `33`・1973 `33`・2013 `34`・2053 `34` |

`NN` の上位 3 ビットは一定（`001`）で、下位 5 ビットが周波数とともに増える（発振器の帯域の
選択とみられる【推定】。境界の式は 24 点からは決めていない＝表で持つ）。分周比の 2 バイトは
メインライン `tda826x.c` と同じ形。

**(3) 復調器の後処理 `0x11`**: `0a ff`  `11 00`  `10` を読み bit1 を立てて書く（`b0` → `b2`）  `03 01`

**(4) TS の選択 `0x11`**（1 つのトランスポンダに複数の TS が載る）:

| レジスタ | 長さ | 内容 |
|---|---|---|
| `0xce` | 16 | そのトランスポンダの TSID の表（2 バイト × 8。空きは `ff ff`）。例: BS-15 で `40f1 40f2 48f3`、BS-1 で `4010 4011 4012` |
| `0xe6` | 2 | いま選ばれている TSID |
| `0x8f`/`0x90` | 2 | 選ぶ TSID（上位・下位）。**`00 00` なら表の先頭** |

- 選ぶには `8f`・`90` に TSID を書き、`03 01`（リセット）を書く。約 1 秒後には `e6` が書いた値になり、
  出てくる TS が替わる（BS-15 で `40f1` → `40f2` → `00 00`（＝`40f1`）と切り替えて確認）。
  メインライン `tc90522.c` の `tc90522s_set_tsid` と同じレジスタ。
- ベンダの UPnP の選局は `8f`/`90` を書かない（電源投入時の `00 00`＝先頭の TS のまま）。
- px4_drv 互換の `slot`（相対番号 0〜7）は、ロックした後に `0xce` の表を読んで TSID に直せばよい。

## 6. 状態の読み出し

### 6.1 地上（`0x10`）

| レジスタ | 長さ | 内容 | 例（ロック／信号なし） |
|---|---|---|---|
| `0x80` | 1 | 同期の段。**`0x00` で最終段**。途中は `0x2f` → `0x28` → `0x08` → `0x00` と下がる | `00` ／ `af` |
| `0x96` | 1 | 階層ごとのロック（bit7＝A、bit6＝B、bit5＝C） | `c4`・`c6`（2 階層）、`84`（1 階層）／ `00`・`04` |
| `0x8b` | 3 | C/N の生の値 | `00 13 a2` |
| `0x82` | 2 | 1 バイトめが AGC（ベンダの UPnP の `Agc` と同じ値） | `67 00` ／ `a1 00` |
| `0xb0` | 1 | 伝送モード・ガードの検出の段（`a0` → `a9`） | `a9` ／ `a0` |
| `0xb2` | 7 | TMCC（階層ごとの変調ほか） | `3d 25 8b 4b 3f ff ff` |
| `0x9d` | 15 | 誤りの計数（階層ごと） | — |

- **ロックの判定**は、メインライン `tc90522.c` の地上側と同じ読み方で足りる: `0x96` の上位 3 ビットの
  どれかが立てばロック。立っていなければ `0x80` を見る（上位 4 ビットが 0 で搬送波、`0x0c` が 0 で
  同期、`0x02` が 0 でロック）。ベンダは選局から約 0.3〜0.9 秒でロックを得ている。
- **C/N**: `0x8b` の 3 バイトを 24 ビットの数 n とし、`P = 10·log10(5505024 / n)`、
  `C/N = 0.000024·P⁴ − 0.0016·P³ + 0.0398·P² + 0.5491·P + 3.0965` dB（メインラインの式）。
  ベンダが UPnP で返す `Cn` は、この値の小数を切り捨てたものと一致する
  （n = `0x13a2` → 32.1 → `32`、n = `0x0b4f` → 35.2 → `35`。ロックした 12 波すべて）。

### 6.2 衛星（`0x11`）

| レジスタ | 長さ | 内容 | 例 |
|---|---|---|---|
| `0xc3` | 1 | 同期の段。**`0x00` でロック**。途中は `0x50` → `0x10` → `0x01` → `0x00` | `00` |
| `0xbc` | 2 | C/N の生の値 | `2d 71` |
| `0xba` | 1 | AGC（ベンダの `Agc` と同じ値） | `1f` |
| `0xeb` / `0xf0` | 5 | 誤りの計数 | — |
| `0xce` / `0xe6` | 16 / 2 | TSID の表 / いまの TSID（§5 の (4)） | `40 f1 40 f2 48 f3 ff…` / `40 f1` |
| `0xc5` / `0xe8` / `0xbb` | 1 | TMCC まわり（波ごとに違う値。意味は未確定） | — |

- **ロックの判定**: メインラインの衛星側と同じく `0xc3` を見る（bit7 が信号なし、`0x60` が搬送波待ち、
  `0x10` が同期待ち）。メインラインはさらに `0xc5` の下位 2 ビットのどちらかが立つことを条件に
  する（ロックした 21 波の `0xc5` はすべてこれを満たす）。ベンダは選局の直後、`0xc3` を間を
  置かずに読み続け（毎秒約 3000 回）、約 0.1〜0.3 秒で `0x00` を得ている。実装は間を置いて読めばよい。
- **C/N**: `0xbc` の 2 バイトを n とし、n ≥ 3000 のとき `P = sqrt(n − 3000) / 64`、
  `C/N = −1.6346·P⁵ + 14.341·P⁴ − 50.259·P³ + 88.977·P² − 89.565·P + 58.857` dB（メインラインの式）。
  ベンダの `Cn`（切り捨て）と一致する（n = `0x2d71` → 15.7 → `15`。ロックした 21 波すべて）。

### 6.3 アッテネータ（地上）

**地上側 `0x10` のレジスタ `1c` の bit4**。**1 で切・0 で入**（復調器の出力ピンが外のアッテネータを
動かしているとみられる【推定】）。読んで bit4 だけ変えて書き戻す（待機中は bit7 が立っているので
`b0`／`a0`、起きているときは `30`／`20`）。

| ベンダの設定 | 線上 | 557 MHz での読み |
|---|---|---|
| アッテネータ切 | `1c` ← `b0`（bit4 = 1） | C/N 32・AGC 103 |
| アッテネータ入 | `1c` ← `a0`（bit4 = 0） | C/N 31・AGC 103 |

設定を切り替えた直後に書かれ、その後の選局・待機・復帰でも保たれる。

## 7. ベンダの ioctl との対応（参考）

OpenIRD の実装はベンダの `/dev/fe_main` を使わない。記録の読み方のために残す
（`_IOC` の type は `0xb0`）。

| nr | 引数 | 意味（観察） |
|---|---|---|
| `0x21` → `0x01` | 56 バイトの構成 → なし | 起動時に 1 回。§2 の (1)〜(4) が流れる |
| `0x27` ×4 | 12 バイト `{0\|1, 1\|2, 値}`（値は 9 バイトめの 1 バイト） | 起動時と、アッテネータの設定のたび。値は切で `1`・入で `0`。§2 の (5)／§6.3 が流れる（4 本のうち I2C に出るのは 2 本） |
| `0x03` | 値渡し | 波の選択。`1` 地上・`2` BS・`3` CS・`6` 待機。§3 の列が流れる |
| `0x0a` | 4 バイト | 衛星の TS の指定。先頭の 2 バイトが TSID（掲示板スキャンで CS の ND4 を受けるとき `70 40 00 00`＝`0x7040`）。UPnP の受信確認の選局では `0` |
| `0x08` | 8 バイト `{f, 0}` | 選局。f は MHz。§4／§5 の列が流れ、戻りの 5 バイトめが成否 |
| `0x04` / `0x05` / `0x06` / `0x07` | 読み | ロック・AGC・波・誤り率（3 語）。約 1 秒おき |

ベンダの設定は無認証の UPnP で見える・変えられる: `X_SetTunerSetting(Attenuator, PowerSupply)` の
引数は文字列 **`ON`／`OFF`**（`true`・`1` などは 402 で拒否される）。いまの値は ContentDirectory の
`Browse`（オブジェクト `32` の下の「チューナー情報」＝`at:attenuator`・`at:powerSupply`、値は `0`／`1`）。

## 8. 未確定

- **GPIO42（出力）の役割**。ベンダアプリの動作中、BS/CS を受けている間だけ 0 になる（給電の設定とは
  無関係）。アンテナへの給電ではない（§8.1）。試作では 1 のままで BS/CS がロックし、C/N もベンダの
  表示と同じだった＝受信には要らない。
- GPIO19〜22（出力）は、ベンダアプリが `/dev/io_controller` 経由で毎秒 5 回書いている（表示灯と
  みられる【推定】）。GPIO21 は選局に合わせて変わるが、試作では触らずに受信できた。
- `0x10` の `47`・`25`・`20`・`23`、`0x11` の `0a`・`10`・`11` の各ビットの意味（書く値は §4・§5 のとおりで足りる）。
- MxL601 の初期化の各値の意味（§2 の列をそのまま書けば動く）。VHF・CATV 帯は、チューナへの
  書き込みは採れたが（§4）、この場所に信号が無くロックは確かめていない。
- BS 7・11・17 ch（IF 1164・1241・1356）はこの場所でロックしなかった（新 4K 8K 衛星放送の
  方式の波とみられる【推定】。チューナの値は表に入れてある）。

### 8.1 アンテナへの給電は無い（確定・2026-10-12）

**この機種は BS・CS アンテナへ電源を供給できない。** LNB の給電の入切は実装の対象にならない
（px4_drv 互換の LNB の ioctl は「対応しない」）。

| 根拠 | 内容 |
|---|---|
| 製品のガイド | SB-TV06-WRIP のガイド（35 ページ）に「BS／CS デジタル放送用アンテナへの電源供給はされていますか？（本製品から電源供給はできません）」。同じ基板系の市販機 PIX-BR310L／PIX-BR310W のセットアップガイドにも同じ記述 |
| 実測 | アンテナ線を外した入力端子（地上・BS・CS 共用の 1 つ）の直流電圧は、ベンダの設定を給電「入」にした状態で、BS の受信確認の選局中・待機中・掲示板スキャン（CS を実際の受信経路で受信）中のどれも 0 V 付近 |
| 設定の切り替え | ベンダの UPnP の `PowerSupply` を `OFF`／`ON` に切り替えても、設定の時にも BS の選局時にも、デバイスへの ioctl は増えず、バス 1 の I2C の書き込み（38 本）も SoC の GPIO（60 本）も変わらない |

∴ UPnP の `PowerSupply`（と ContentDirectory の `at:powerSupply`）は、値を覚えるだけで、この基板では
何も動かさない（ほかの機種と共通のソフトの名残とみられる【推定】）。

## 9. 検証

| 項目 | 結果 |
|---|---|
| 初期化の列（§2） | 2 回の起動で完全に一致 |
| 地上の選局の列（§4） | UHF 50 波と VHF・CATV 帯 64 点（93〜471 MHz）で、周波数の語と 2 値以外は同じ。この場所でロック 13 波（ch 13・16〜19・21〜27・60） |
| 衛星の選局の列（§5） | BS 12 波・CS 12 波。この場所でロック BS 9 波・CS 12 波 |
| C/N の式と AGC（§6） | 掃引でロックした 33 波（地上 12・BS 9・CS 12）すべてで、式の値の切り捨てがベンダの `Cn` と一致。AGC は生の値が一致 |
| メインラインとの対応（§3〜§6） | 待機・復帰・AGC の切り替え・リセット・状態のレジスタが `tc90522.c` と対応（v6.6 で確認） |

**試作での実証（2026-10-12）**: この仕様だけから書いたシェル
[`tools/wrip-fe/wrip-fe.sh`](../../tools/wrip-fe/wrip-fe.sh)（`/dev/i2c-1` に読み書きするだけ）を、
**ベンダアプリ抜きの起動**（ベンダのフロントエンドのモジュールは load されているが、
`/dev/fe_main` には 1 度も触れない）で動かした。

| 手順 | 結果 |
|---|---|
| GPIO43 を 1 → `init`（§2） | 全書き込みが ACK |
| `t 557`（§3・§4。TMCC の先渡しなし） | ロック（`80=00`・`96=c4`）。C/N の生の値 `0x13e5`（32.0 dB）・AGC `0x67`＝ベンダの表示と同じ |
| `s 1318`（§3・§5） | ロック（`c3=00`）。C/N `0x2d71`（15.7 dB）・AGC `0x1f`＝ベンダの表示と同じ |
| `s 1613`・`s 1049`・`t 503`・`t 521` | ロック。`t 479`（信号なし）は `80=af` |
| `sleep` → `t 521` | 待機で `03=90`・`1c=b0`（ベンダと同じ）。復帰してロック |
| TSID の切り替え（§5 の (4)） | `40f1` → `40f2` → `00 00` で `e6` と TS が替わる |
| GPIO43 を 0 → 1 | 0 で応答なし。1 に戻すとレジスタは初期値。`init` からやり直してロック |

読み出しは繰り返し START（書き込みと読みを 1 回の転送にまとめる形）で行った。
