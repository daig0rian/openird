# OpenIRD

**Open firmware for network tuner appliances.**

OpenIRD は、ネットワーク接続型のチューナー機器（受信機）のための、オープンで共通のファームウェアプロジェクトです。OpenWrt の設計思想と開発手法を踏襲しつつ、その対象をルーターから「IRD（Integrated Receiver Decoder）＝受信・復号機能を内蔵したネットワーク機器」へ置き換えます。

機器ごとに閉じたメーカー純正ファームウェアではなく、単一のコードベースから複数機種向けのイメージを生成します。メーカーのサポートやクラウドサービスが終了した後も、機器の所有者が自分の機器を使い続けられることを目的とします。

表記は `OpenIRD`（O と IRD が大文字、間にスペースなし）です。リポジトリ名・パッケージ名・ドメインでは小文字 `openird` を用います。

---

## このプロジェクトが目指すもの

- **機器の延命** — サービス終了・サポート終了後も、受信機を動かし続けられるようにする。
- **開放性** — 所有者が自分の機器のソフトウェアを理解し、変更し、共有できるようにする。
- **共通基盤** — 機種ごとの再発明を避け、単一のコードベースで複数機種を扱う。

当面の現実的な主眼は、**既存の市販機に対する対応機種を増やすこと**です。名前から連想される放送規格に依存しない汎用化やオープンハードウェア化は、拒みはしませんが、遠い将来のゴールと位置づけます。

### 対象範囲

- **当面の対象**：日本の ISDB-T / ISDB-S 機器。
- **設計上の非依存**：特定の放送規格に依存しない構造を保ち、将来 DVB / ATSC を受け入れる余地を閉じません。

## スコープ

OpenIRD が担当するのは、チューナーデバイスをLinux から扱えるハードウェア(chardev等)にするところまでです。選局・復調・ストリーム取出しのインターフェースを提供します。それ以降の仕事は OpenIRD の外側の仕事ですが、上位のプログラムを機器に載せるための仕組みは提供します。

**範囲内**

- フロントエンド（RF チューナー／復調 IC）の制御 — 選局、復調、誤り訂正
- TS を取り出すためのインターフェース（キャラクタデバイス）の提供と、その ABI の維持
- 機器を動かす基盤 — Linux カーネル、ユーザランド、ネットワークスタック、機器自身の設定・管理 UI
- 上位のプログラムを機器に載せるための仕組み（パッケージ feed）

**範囲外**
- 限定受信（B-CAS / ARIB の限定解除）
- チューナー制御スタック、EPG 取得、録画管理、番組配信サーバ、視聴用フロントエンド
- 映像・音声のデコード（MPEG-2 / H.264、AAC）と再生

OpenIRD はスクランブル解除を実装せず、関連する鍵・手順・回避技術を扱いません。これはプロジェクトの健全性を守るための明確な境界であり、議論の対象ではありません。OpenIRD が担当する層には、そもそもそれが入る場所がありません。

## 技術的な土台

OpenIRD は **Buildroot** をベースとし、機器のベンダ Linux カーネル（多くは古い世代の BSP）を生かしたまま、その上に新しくクリーンなユーザランドとイメージパイプラインを載せます。これは OpenWrt そのもののフォークではなく、**OpenWrt の方法論を Buildroot 上で再現する**アプローチです。IP カメラ向けの [OpenIPC](https://openipc.org/) が同じ構造（Buildroot 外部ツリー・ベンダカーネル温存・機種ごと defconfig）を採っており、最も近い先行事例です。

OpenWrt から受け継ぐのは実装ではなく、以下の**設計思想と語彙**です。

- 単一コードベースから複数機種のイメージを生成（機種ごとの宣言的定義）
- `factory` イメージ（純正の更新機構経由で初回導入）と `sysupgrade` イメージ（導入後の自己更新）の分離
- パッケージ feed による機能の分離
- 統一された設定レイヤと Web UI

## 配布物のクリーンさに関する方針

**OpenIRD が配布するイメージには、実機から吸い出したベンダ由来のバイナリを一切含めません。**

- カーネルは各機種の GPL 公開ソースから再ビルドします。
- 基本ユーザランドは Buildroot で新規にビルドします。
- スコープの実現が公開されていない実機コードに依存する場合、観察から起こした仕様に基づくクリーンな実装が実現した場合のみ、その結果を配布物に含めることができます。

機種ごとの対応状況は対応機種表（今後追加）を参照してください。

## OpenWrt / OpenIPC との関係

OpenIRD は OpenWrt の設計思想に強く影響を受けていますが、**OpenWrt プロジェクトの公式なものではなく、関係もありません**。同様に OpenIPC の公式なものでもありません。これらのプロジェクトの商標を、OpenIRD が承認・提携を示唆する形で用いることはありません。
