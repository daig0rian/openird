# OpenIRD

**Open firmware for network tuner appliances.**

OpenIRD は、ネットワーク接続型のチューナー機器（受信機）のための、オープンで共通のファームウェアプロジェクトです。OpenWrt の設計思想と開発手法を踏襲しつつ、その対象をルーターから「IRD（Integrated Receiver Decoder）＝受信・復号機能を内蔵したネットワーク機器」へ置き換えます。

機器ごとに閉じたメーカー純正ファームウェアではなく、単一のコードベースから複数機種向けのイメージを生成します。メーカーのサポートやクラウドサービスが終了した後も、機器の所有者が自分の機器を使い続けられることを目的とします。

表記は `OpenIRD`（O と IRD が大文字、間にスペースなし）です。リポジトリ名・パッケージ名・ドメインでは小文字 `openird` を用います。

---

## このプロジェクトが目指すもの

- **機器の延命** — サービス終了・サポート終了後も、受信機を動かし続けられるようにする。
- **開放性** — 所有者が自分の機器のソフトウェアを理解し、変更し、共有できるようにする。
- **共通基盤** — 機種ごとの再発明を避け、単一のコードベースで複数機種を扱う。

当面の現実的な主眼は、**既存の市販機に対する対応機種を増やすこと**です。名前から連想される放送規格に依存しない汎用化やオープンハードウェア化は、拒みはしませんが、遠い将来のゴールと位置づけます。

### 対象範囲

- **当面の対象**：日本の ISDB-T / ISDB-S の受信機。チューナーは、日本の DTV コミュニティで標準的なキャラクタデバイス（px4_drv 互換）として見せます。

## スコープ

OpenIRD が担当するのは、チューナーデバイスをLinux から扱えるハードウェア(chardev等)にするところまでです。選局・復調・ストリーム取出しのインターフェースを提供します。それ以降の仕事は OpenIRD の外側の仕事ですが、上位のプログラムを機器に載せるための仕組みは提供します。

**範囲内**

- フロントエンド（RF チューナー／復調 IC）の制御 — 選局、復調、誤り訂正
- TS を取り出すためのインターフェース（キャラクタデバイス）の提供と、その ABI の維持
- 機器を動かす基盤 — Linux カーネル、ユーザランド、ネットワークスタック、機器自身の設定・管理 UI
- 上位のプログラムを機器に載せるための仕組み（アドオン）

**範囲外**
- 限定受信（B-CAS / ARIB の限定解除）
- チューナー制御スタック、EPG 取得、録画管理、番組配信サーバ、視聴用フロントエンド
- 映像・音声のデコード（MPEG-2 / H.264、AAC）と再生

OpenIRD はスクランブル解除を実装せず、関連する鍵・手順・回避技術を扱いません。これはプロジェクトの健全性を守るための明確な境界であり、議論の対象ではありません。OpenIRD が担当する層には、そもそもそれが入る場所がありません。

## 技術的な土台

OpenIRD は **Buildroot** をベースとし、機器のベンダ Linux カーネル（多くは古い世代の BSP）を生かしたまま、その上に新しくクリーンなユーザランドとイメージパイプラインを載せます。これは OpenWrt そのもののフォークではなく、**OpenWrt の方法論を Buildroot 上で再現する**アプローチです。IP カメラ向けの [OpenIPC](https://openipc.org/) が同じ構造（Buildroot 外部ツリー・ベンダカーネル温存・機種ごと defconfig）を採っており、最も近い先行事例です。

OpenWrt から受け継ぐのは実装ではなく、以下の**設計思想と語彙**です。

- 単一コードベースから複数機種のイメージを生成（機種ごとの宣言的定義）
- `factory` イメージ（純正の更新機構経由で初回導入）と `sysupgrade` イメージ（導入後の自己更新）の分離
- 機能の分離 — イメージに組み込む**ビルドオプション**と、動いている機器へ後から載せる**アドオン**（[docs/addon.md](docs/addon.md)）。OpenWrt の feed に当たるものですが、OpenIRD ではこの 2 つが互換のない別の仕組みなので、語を分けています
- 統一された設定レイヤと Web UI

## 配布物のクリーンさに関する方針

**OpenIRD が配布するイメージには、実機から吸い出したベンダ由来のバイナリを一切含めません。**

- カーネルは各機種の GPL 公開ソースから再ビルドします。
- 基本ユーザランドは Buildroot で新規にビルドします。
- スコープの実現が公開されていない実機コードに依存する場合、観察から起こした仕様に基づくクリーンな実装が実現した場合のみ、その結果を配布物に含めることができます。
- 動作に、機器に元から入っている部品（ファームウェアなど）が要る機種があります。その場合も OpenIRD はそれを配布せず、所有者の機器に残っているものを実行時に読み取るだけです。

機種ごとの対応状況は、下の「プロジェクトの現状」を参照してください。

## プロジェクトの現状

2026 年 10 月時点。初期開発段階ですが、最初の 1 機種（BMMPX1301）で、**GPL ソースから再ビルドしたカーネルと Buildroot で新規に作ったユーザランドだけのイメージが実機で動き、放送を受信して TS を取り出せる**ところまで到達しました。

### 対応機種

| 機種 | SoC / カーネル | Linux 基盤 | チューナー |
|---|---|---|---|
| BMMPX1301（POE-BR100-YB1） | Renesas EMMA3SEP（MIPS ビッグエンディアン）/ Linux 2.6.27 | 実機で動作 | 地上デジタル（ISDB-T）を受信できる |
| SB-TV02-WFPL | Fujitsu MB86H61（ARM）/ Linux 2.6.31 | 実機で動作 | 提供できない（下記） |
| SB-TV06-WRIP（POE-BR310L-SB1） | Renesas EMMA3SEP / Linux 2.6.27 | 未対応（導入経路の確認まで） | 未対応 |

### BMMPX1301 でできること

- **受信** — 観察から起こした仕様だけを見て書いたドライバ（`ird-tuner-*`、カーネルに組み込み）が、px4_drv 互換のキャラクタデバイス `/dev/irdvideo0` を提供します。取り出すのはスクランブルされたままの TS です。未改造の recpt1 でそのまま録画でき（連続性エラー 0）、別の受信機（PX-M1UR）で同時に録った TS とビット単位で一致することを確かめています。
- **基盤** — GPL 公開ソースの Linux 2.6.27.39 を再ビルドしたカーネルと、musl ＋ BusyBox ＋ dropbear のユーザランド。読み取り専用の rootfs に書き込み可能な層を重ねてあり、設定や追加したソフトは再起動をまたいで残ります。
- **アドオン** — イメージを焼き直さずに、動いている機器へ後からソフトを載せる仕組み（`ird-addon`）。recpt1 のような上位のプログラムはこれで載せます。アドオン作者向けの SDK（クロスツールチェーン一式）を Releases に置いています。
- **導入** — 純正の更新機構（UPnP）に渡すコンテナを `openird-mkimage` が作り、`openird-fwup` が機器へ渡します。更新用の鍵は OpenIRD に含まれません。所有者が自分の機器から得た値を渡します。

知っておくべき制約:

- 受信の立ち上げに、機器に元から入っている 3 つの部品（AV 用サブ CPU のファームウェア、それを起動するカーネルモジュール、復調器のファームウェア）を実行時に使います。OpenIRD はこれらを配布せず、純正の区画を残したまま読み取るだけです。
- 取り出せる TS はヌルパケットを除いたものです。機器が忙しいときに、まれに 1 パケット欠けることがあります。
- `openird-fwup` は、実機での投入をまだ確かめていません。機器に入れるイメージ（factory / sysupgrade）の配布もまだ行っていません。
- 設定レイヤと Web UI は未実装です。

### SB-TV02-WFPL

自前のカーネルとユーザランドが実機で動きます。ベンダの区画配置を OpenWrt 流に切り直し（読み取り専用 rootfs ＋ overlay ＋ 復旧用区画）、squashfs ＋ overlayfs の書き込み可能な root と SSH までを確かめました。

チューナーは提供できません。この機種では、復調器の出力が外付けのトランスコーダ IC に入り、スクランブル解除がその IC の中で行われます。SoC に届くのは解除後の出力だけで、スクランブルされたままの TS をソフトウェアから取り出す経路がありません。OpenIRD はスクランブル解除を扱わないので、この機種の対応範囲は「Linux が動くネットワーク機器」までです。

### SB-TV06-WRIP

BMMPX1301 と同じ SoC の、地上・BS・CS の 3 波機です。純正の更新機構で自作のコンテナを書き込めることまでを確かめた段階で、OpenIRD のイメージはまだありません。

## OpenWrt / OpenIPC との関係

OpenIRD は OpenWrt の設計思想に強く影響を受けていますが、**OpenWrt プロジェクトの公式なものではなく、関係もありません**。同様に OpenIPC の公式なものでもありません。これらのプロジェクトの商標を、OpenIRD が承認・提携を示唆する形で用いることはありません。
